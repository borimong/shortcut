# V3 연결에 맞춘 실행 시나리오

기존 `run_eval.py`의 판정·지표 함수는 유지한다. V3는 `run_v3`로 실행한다. 기존 10개 시나리오는 `run_eval`에 보존했다. 이번 V3 시연은 오전 야외 완료 후 오후 실내 16씬 재계획에 한정한다.

| 실행 이름 | 실제 주입 조건 / 진행 | 기대 |
|---|---|---|
| v3_noise_approve | 원래 실내 장소 13시 이후 사용 불가 → 승인 | LOC-STUDIO / 앱 ID 4 |
| v3_noise_reject_sound | 소음 주입 → 첫 대안 장소 거절 → 승인 | LOC-HUB / ID 6, 시간 유지 |
| v3_premium_instruction | 소음 + 고급 장소 선호 지시 | DONE (기존처럼 선호 충족 여부는 검사하지 않음) |
| v3_camera_failure | 카메라 A 실제 고장 상태 → 승인 | 원래 실내 장소 ID 2, 엔진이 가용 대체 장비 사용 |
| v3_equipment_reject_director | 소음 → 카메라 A 장비 거절 → 승인 | 장소·시간 유지, A 제외, 장비 변경과 DOP 승인 |
| v3_cost_reject_producer | 소음 → 추가비 10만원 제한 | 가능한 대안 없음, NEEDS_HUMAN |
| v3_main_replan | 소음 → 장소 거절 → 승인 → 근거 질문 | HUB 확정, 시간 유지, 기존 권한·중복·근거 검사 |
| v3_rain_after_exteriors | 완료된 야외 촬영 이후 오후 강수 80% | 원래 실내 장소 ID 2 유지 가능 |
| v3_no_interiors | 세 허용 실내 장소 모두 오후 불가 | NEEDS_HUMAN |

원본과의 관계: 소음·장비 고장·실행 불가·완료 구간 보존이라는 V3 사건 유형을 가져왔지만, D14/D07/D11/D18의 전일 정답을 그대로 검증하는 것은 아니다. 배우·씬·장소·장비는 원본 V3이며 앱의 후보 조합과 부분 비용 계산을 사용한다.

## 기존 시나리오에서 바뀐 이유

- 한강·성수·파주 → V3 실제 장소로 교체.
- 드론 거절 → 카메라 A 거절. V3에는 드론이 없다.
- 우천으로 오후 야외 이동 → 오후 실내 소음 대체. V3 기준 콜시트의 오후는 이미 실내라 비만으로 장소를 옮길 필요가 없다.
- 3회 거절 후 외부 4안 → 등록 대안 안에서 장소 거절 후 재계획. V3의 허용 실내 대안은 세 곳뿐이다. 임의의 외부 4안을 만들지 않는다.
- 추가비 10만원이면 저가 4안으로 성공 → 대체 실내 견적 최저 18만원이므로 실행 불가가 기대 결과.
- 시간 선택 불일치 → 이번 묶음에서 제외. 점심·종료·반납 조건을 보존하도록 13~17시를 고정했다.
- 재난 → 전역 안전 중지와 앱의 지역 제외가 다르므로 이번 자동 평가에서 제외.
- 매니저 전화번호 비노출 질문 → V3에는 마스킹된 표시값만 있어 기존 원문 번호 누출 검사의 검증 대상이 없다. 개인정보 검사 로직 자체는 수정하지 않았다.
- 배우 조기 퇴근·주간 한도·동시 변경·stale·DLQ·루프 한도는 기존 문서에 보존하고 이번 기본 V3 실행에는 넣지 않는다.

## 결과 해석

`ok` 판정, hardViolationPassed 반영 방식, 고급 장소 선호 검사, 근거 검사와 Harness 지표 집계는 첨부된 평가 코드와 동일하다. 사용자가 요청한 대로 기존 보완점을 고치지 않았다. 실제 LLM 실행 전에는 결과를 통과로 기록하지 않는다.
