# 공개 입력 사용법

기준 snapshot은 base/world.json이다. 같은 정보를 base·catalogs에도 테이블별로 제공한다. plan_sets에는 사건 전 제작사가 준비한3개 대비안이 있다. 대비안2·3은 실제 예약 완료가 아니다.

현재 사건 한 건의 facts를 함께 제공하고 원본에서 시작한다. 시각은 Asia/Seoul 자정 기준 분, 구간은 시작 포함·종료 제외다. 대부분10월22일18시의 전날 통보이며 D18은 촬영 도중 통보다. missing_fields는 원본 값이 남아 있어도 확인이 끝나지 않은 사실이다. STOP_ALL은 다른 최적화보다 먼저 처리한다.

RAG에는 rag/chunks.jsonl만 넣거나 documents.json의 index_in_rag=true인 원문을 색인한다. business_documents의 대본·견적은 업무 도구 자료다. 최신 가격·예약·예보·달력은 사건 facts를 반영한 업무 조회가 기준이다. get_entity_context는 현재 계약을 특정하고 search_active_contract는 해당 인물·문서·버전으로만 범위를 제한한다.

응답은 case_id, decision, selected_plan, missing_fields, explanation, approval_request_plan_count를 가진다. selected_plan은 한 개 객체 또는 null이며 여러 최종안을 배열로 내지 않는다. 내부 탐색 후보는 여럿일 수 있다. FEASIBLE·CONDITIONAL_ONLY일 때 승인 요청 대상은 한 개, 불가능·질문·갱신·안전 중지일 때는0개다. 구조는 integration/response_schema.json을 참고한다.

selected_plan에는24개 씬 블록,5명 콜,장비5종,비용 상세,취소 항목,사전안 요소 출처,현재 계약 참조,5개 하드 체크,6개 점수·가중치,필수 승인자 ID,예약 작업,외부 조건,사건 리비전,자원 버전,해시가 필요하다. integration/rules.py로 검증하고 해시는 rules.plan_hash로 계산한다.

장소 변경에는 음향감독,장비 변경에는 장비감독,추가비에는 예산권한자가 추가된다. 조감독 두 명은 각자 응답해야 한다. 필요한 확인 조건과 담당자 예약 완료 전에는 발행하지 않는다. 한 명 거절 시 사유를 새 제약으로 추가하고 새 안에 전원 재승인을 요청한다. provider=OURPLACE_MOCK는 실제 API·게시물·예약이 아니다.

공개 함수는 연결 예시이며 인증 서버·MCP 서버·LangGraph·CP-SAT·알림 서비스가 아니다. 승인 대기 동안 모델을 반복 호출할 필요가 없으며 thread·제안 해시·승인 상태를 저장하고 응답 이벤트로 재개한다. 실행 결과나 정답 자료를 이 입력 범위에 섞지 않는다.
