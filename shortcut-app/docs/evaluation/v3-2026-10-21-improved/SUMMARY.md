# V3 실패 개선 후 실제 재평가

실제 모델·MCP·RAG·승인 API로 같은 9개 시나리오를 한 차례 순차 실행해 **9/9 통과**했다. 이전 실행은 6/9였다. 평가 함수와 V3 시나리오 파일은 변경하지 않았다.

| 이전 실패 | 개선 | 재평가 |
|---|---|---|
| 장비 거절 후 전체 장비 제외 제약을 생성하다 FAILED | 명시된 후보 장비 ID를 검증하고 해당 장비만 제외. 모호한 요청은 대상·금액 전용 추출 스키마 사용 | 카메라 A 제외, B 선택, 장소·시간 유지, DOP 승인 추가 후 DONE |
| 추가비 10만원 거절 시 장비 제약까지 생성하다 FAILED | 원화 금액을 해석하고 COST 선택일 때 비용 제약만 구성 | 후보 없음 확인 후 NEEDS_HUMAN / NO_FEASIBLE_PLAN |
| 대표 재계획 후 근거 질문에 출처 없음 | 질문에 최신 확정 제안을 연결하고 검증된 근거를 미리 조회. 근거가 없을 때 검색 보완. 답변의 인용 ID 검증 | 장소 확정 및 후속 출처 검사 모두 통과 |

## 추가한 방어 처리

- 구조화 응답 검증 실패 시 오류와 이전 인자를 알려 주고 한 번만 수정 요청한다. 토큰·재시도 계수도 집계한다.
- 모호한 장비 거절에서 실제 후보의 장비를 특정하지 못하면 사람 확인으로 분기한다.
- 근거 질문의 인용이 누락되거나 존재하지 않는 ID를 쓰면 한 번 수정 요청한다. 여전히 연결하지 못하면 확인이 필요하다고 답한다.
- 답변에서 실제 인용한 검색·제안 근거만 sources로 반환한다. 질문만으로 새 출처를 만들지 않는다.

## 평가 버전과 해석 범위

이번 실제 평가 버전은 [`20aff19`](https://github.com/borimong/shortcut/commit/20aff19c79bd188a0013d56f81d63fe5f0860b3b), 이전 6/9 버전은 `c869e92`다. 코드·데이터 버전과 테스트 수는 [provenance.json](provenance.json)에 기록했다.

두 실행 사이에는 최신 main의 팀원 수정도 포함되어 있다. 6/9 → 9/9의 변화 전체를 이번 수정만의 효과로 분리한 실험은 아니다. Agent 장기 기억도 기존 실행 방식대로 초기화하지 않았다. 같은 입력의 단일 실행 결과이며 반복 성공률을 뜻하지 않는다.

평가 범위는 오전 8씬 고정·오후 16씬 재계획이다. 전일 24씬 재배치·분장·주간 이력·전체 비용 모델 평가는 아니다. 기존 근거 지표는 여전히 제안이 있던 건의 5/7이며, 모든 근거 범주를 채웠다는 뜻은 아니다. 고급 장소 선호 검사는 기존대로 DONE 여부만 판정한다. 기존 hardViolationPassed 필드에는 위반 목록 유무가 저장되므로 False가 위반 없음이며, 이 집계 코드는 수정하지 않았다.
