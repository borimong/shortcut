## 실패 원인

1. 장비 거절(task 5): `RejectionPlan.constraints`는 최대 3개인데 모델이 5개의 장비 제외 제약을 만들어 검증 오류가 발생했다. 로그상 3회 시도 후 FAILED.
2. 예산 거절(task 6): 모델이 비용 제약과 장비 제외를 합쳐 6개의 제약을 만들어 같은 최대 3개 제한에 걸렸다. 기대한 사람 인계가 실행되지 않았다.
3. 대표 재계획(task 7): 장소를 HUB로 변경하고 콜시트를 확정했으나, 후속 질의응답에서 출처를 반환하지 않아 기존 SOURCES 검사에서 실패했다. 출처 누락의 내부 원인은 이번 결과만으로 확정하지 않았다.

## 해석 시 주의

- 이 결과는 한 번의 실행이다. 실패를 성공으로 바꾸기 위한 재실행이나 평가 조건 완화는 하지 않았다.
- 확정된 6건은 기존 평가 코드의 사후 검증에서 하드 제약 위반 0건으로 집계됐다. `hardViolationPassed` 필드는 현재 코드에서 위반 목록 유무를 저장하므로 이름과 반대로 False가 위반 없음이다. 요청에 따라 수정하지 않았다.
- 제안이 있었던 사례의 evidenceCoverage는 5/7이다. 7범주의 근거 완비로 해석하면 안 된다.
- 실패한 2건의 토큰·비용·지연은 기존 결과 수집에서 null이다. 성공 건만 합친 값은 전체 실행 비용이 아니다.
- LangSmith 인증 실패 로그가 있어 외부 trace 링크는 생성되지 않았다. OpenAI 요청과 앱 자체 평가 실행은 진행됐다.
- 평가기는 시나리오 전마다 앱 업무 데이터를 초기화한다. 시나리오별 주요 결과는 JSON/MD에 보존했으며 Agent 장기 기억은 기존 코드대로 초기화하지 않았다.
